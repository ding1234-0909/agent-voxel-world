# 接入 AI 玩家

DeepSeek 玩家与服务端托管 Agent 复用 `@voxel/agent-runtime` 中的 `Session`，通过 OpenAI 官方 Node SDK 连接 `https://api.deepseek.com`，运行“观察 → JSON 动作序列决策 → 整批校验 → 顺序执行与逐步观察 → 汇总结果”循环。它不是 Voice Lab 的语音聊天提供商，也不是原有固定脚本 Scout。

## 代码职责与依赖

`apps/agent` 只保留可执行入口和 DeepSeek 环境变量解析。可复用代码位于 `packages/agent-runtime`，服务端和 CLI 均通过包入口引用，服务端不依赖 CLI 源文件。

```text
apps/agent/
├── src/cli/
│   ├── scout.ts            # pnpm agent
│   ├── deepseek.ts         # pnpm agent:deepseek，加载根目录 .env
│   └── deepseek-config.ts  # DeepSeek 专用环境变量与默认值
└── test/integration.ts     # pnpm test:integration，需要 PostgreSQL 世界

packages/agent-runtime/src/
├── index.ts                # 明确列出的公共 API
├── contracts.ts            # 会话、动作、决策、配置与 Planner 接口
├── errors.ts               # AgentRuntimeError
├── client/session.ts       # Colyseus 连接与世界协议
├── actions/                # 动作解析、执行和连续建造
├── planner/                # OpenAI 兼容适配、提示词和决策解析
└── runtime/                # 任务状态、消息关注队列、单步执行与 CLI 循环
```

`contracts.ts` 仅依赖共享协议类型；任务执行依赖 `Planner` 接口，不依赖具体模型实现。模型规划器和任务执行器共享动作/任务解析规则；包内使用具体模块路径，避免通过公共入口反向导入形成循环。公共入口不加载 `.env`、注册退出信号或启动 Agent。

服务端 `AgentManager` 保留调度权：每次唤醒调用一次 `runTaskStep`，空轮询和等待条件未变化时不推理。CLI 使用 `runAgent` 驱动循环并在任务停止时退出。`ModelPlanner` 支持 DeepSeek、Ollama 和 OpenAI 兼容接口；`pnpm agent:deepseek` 仍使用 DeepSeek 专用配置和启动提示。

## 大厅控制台（推荐）

### 多动作决策

一次模型调用可以规划 **1–8 个顺序动作**。CLI 和控制台托管 Agent 共用执行器；动作之间无需等待轮询间隔，移动、编辑和建造后会重新观察，后续动作使用最新位置与世界版本。刷新观察本身不调用模型。

```json
{
  "actions": [
    { "type": "move", "x": 1, "z": 0, "jump": false, "durationMs": 300 },
    { "type": "edit", "x": 2, "y": 3, "z": 1, "material": "wood" },
    { "type": "chat", "text": "已尝试放置，接下来检查目标是否完成。" }
  ],
  "task": {
    "intent": "continue",
    "status": "running",
    "summary": "靠近施工位置并放置方块，下一轮确认目标"
  }
}
```

坐标必须根据实际观察选择。模型仅接受 `{actions, task}` 格式，两个字段均必填；即使只有一个动作也须放入 `actions` 数组。旧平铺动作、`{action, task}`、缺少 `task` 或混合格式均会被拒绝，不执行动作。整个序列先校验，任一非法或越权动作导致整批不执行。`wait` 只能位于末尾，每批最多一个 `build` 或 `house`；回复和暂停/恢复/取消只能携带聊天或等待动作。连续聊天间隔至少 350ms。

- 顺序执行，失败、超时或观察失败就停止剩余动作；不回滚已成功的修改。单个建造动作仍沿用自身的逐块施工和已确认冲突处理规则。
- 非零移动后，位置变化不足 0.05 格会停止批次并交回模型。发生位移仅表示有进展，不证明到达目标或全程没有碰撞；没有自动寻路或目标位置条件。
- 普通消息在当前顶层动作结束后让出执行，`build`/`house` 算一个动作。明确暂停/取消仍能立即打断推理、移动或逐块施工。已排队的单次回复至少处理其首个动作，避免下一条消息使当前回复静默丢失。
- `previous.previous` 返回整批 `actions`、逐步 `results`、未执行的 `remaining`、`ok` 和 `stopReason`。步骤状态包括 `pending`、`executing`、`succeeded`、`failed`、`interrupted`、`unknown`，移动还记录执行前后坐标。
- 请求发出但没有确认时标为 `unknown`，后续需观察并重新规划；剩余动作只作为上下文，不自动续播。建造单独保留已确认修改、剩余方块和未确认请求。只有观察范围与 500 块截断边界内的确切空格才能用于确认删除。
- 一批只计一次模型调用。修改世界或移动的批次不能直接结束任务，仍需后续模型回合验证目标；普通聊天的结果不覆盖当前任务进度。

运行记录显示当前第几个动作、批次停止原因和未执行动作数。输出 token 配置保持原值；模型输出 JSON 被截断时整批拒绝，不能执行已输出的前半段，可按需要在控制台调整输出上限。

### 连续建造

开启“允许放置 / 移除方块”后，所有服务商的 Agent 都支持一次推理规划多块建造：

- `house`：用最小角坐标、宽深高、材质和门方向描述一座基础房屋，本地生成地板、空心墙壁、两格高门洞和平顶。宽/深 3–7 格，总高度 4–6 格；单个蓝图最多 192 块。
- `build`：一次提交 1–64 个具体方块修改，适合自定义结构、修补和拆除。坐标不能重复。
- 批次内约每 125 毫秒执行一块（上限约 8 块/秒，实际还取决于服务器响应），无需逐块推理或等待轮询间隔。每块等待服务器确认，沿用版本号、6 格距离、支撑、玩家占位等校验。
- 已存在且材质相同的方块会跳过；不同材质不会自动覆盖。房屋内部/门洞发现已有方块时，先报告障碍，不自动清理地形。中途停止不会回滚已完成方块。
- 遇到超距或障碍，返回完成数量、剩余坐标与失败原因。未完成蓝图保留到后续回合；模型需要移动站位或调整蓝图后继续，施工器不自动寻路。房屋应放在已观察到的空地上。

可以设置目标：“在附近空地使用 house 蓝图建造一座 3×3 小木屋，留出门洞；遇到超距先移动，再继续未完成蓝图，完成后报告结果。”一座 3×3×4 小屋包含 32 块，能由一次模型规划驱动，而非每块调用一次模型。较复杂的大房屋可以分段建造。

控制台运行记录会显示建造开始、阶段进度和完成/未完成数量。修改后需重载 Agent 服务，再创建新的 Agent；运行中的旧进程不会热替换施工逻辑。

无需先进入游戏。点击大厅中央的 **创建 Agent 玩家**，或右上角 **控制台**。控制台统一提供 **Agent 玩家**、**模型服务商**、**文本转语音（TTS）** 和 **语音识别（ASR）** 四个页面；语音配置保存后可供多个 Agent 复用，试听在关闭或切换页面时停止。

1. 在 **模型服务商** 中添加或编辑 DeepSeek、本机 Ollama、OpenAI 兼容服务。填写 API Base URL、默认模型和 API Key；本机 Ollama 不需要密钥。
2. 保存后切换到 **Agent 玩家**，选择服务商，点击 **测试连接 / 获取模型列表**，选择或手动填写模型 ID。这个按钮只读取模型列表，不执行推理；不提供模型列表接口的网关仍可手动填写。
3. 设置昵称、初始任务和推理参数。轮询保留 **固定间隔** 和 **随机区间** 两种方式。每次唤醒最多调用模型一次，完成动作批次后再安排下一次检查，不并发推理。方块修改默认关闭。
4. 在“语音服务”中选择已保存的音色配置，或保留仅文字回复；可先试听。
5. 点击 **创建并加入世界**。Agent 以 `ai-agent` 身份加入世界，开始初始任务；角色卡片显示任务目标、进展、停止原因和调用/token 用量。

### 聊天与任务

- 普通私聊、群聊 @、可听范围内真人语音转写：处理当前消息一次。问候、询问进度不会重新启动旧任务。
- 行动指令执行后会私密回执给发送者；格式错误、预算不足也会提示，避免静默丢弃消息。移动后会继续观察自身位置，不以方块变化作为确认移动结果的条件。
- 明确的任务指令：模型返回 `task` 决策，创建任务；补充要求用 `update`，保留原任务上下文和未完成蓝图。
- 每步根据观察和动作结果决定继续、完成、等待环境变化、请求用户输入或报告阻塞。实际编辑/移动后至少再观察一次才能标记完成，未完成蓝图不能直接宣称成功。
- 等待时只在本地比较附近方块或玩家位置；条件未变不调用模型。已完成、暂停、取消、阻塞或预算耗尽均不自动推理。
- 连续三次动作失败或没有实际进展会停止自动尝试。语音/文本回复不会成为另一个 Agent 的自动唤醒源。
- 正在执行时收到消息会排队，最多 8 条并去重。同一角色一次只运行一个决策；明确的“暂停”“暂停任务”“停止”“别建了”“取消任务”可直接中断推理/施工，不需要模型判别。其他表达由下一次模型决策判断。

**发送范围不决定执行次数**。私聊可以布置任务，群聊 @ 也可以只是问候。私聊任务保留原接收范围，后续任务汇报也只发送给发起者；公共问题不会收到私聊任务的上下文。任务由玩家发起时，只允许该会话修改当前任务；控制台可覆盖安排。普通群聊、历史消息和 Agent 消息不唤醒。

### 控制台操作与预算

最多同时在线 4 个托管 Agent（含待命）。**布置新任务** 替换任务但保留角色和建筑；**暂停任务** 保留进度；**继续任务** 从当前状态继续；**取消任务** 取消规划但不移除已经放置的方块；**关闭 Agent** 才离开世界。关闭面板或真人退出不关闭 Agent。

**编辑参数** 可修改模型、昵称、初始目标、轮询区间、预算、推理、权限和语音服务。保存不立即启动任务；修改目标/模型/权限后进入暂停。语音回复开关仍可在运行期间切换。

“高级参数”中的 `maxTurns` 现在是任务调用保护上限（默认 100，范围 1–200），不是执行轮数。另有任务 token 预算（默认 50,000）和有效执行时间上限（默认 15 分钟，累计模型与动作耗时，不计等待）。达到上限后停止，控制台 **确认追加预算并继续** 才开启下一额度，累计用量不清零。旧 `continuous` 只保留读取兼容，不再绕过限制。

模型返回 usage 时记录真实 token 数；缺少 usage 时用输入字符与最大输出长度估算并标记“约”。预算在每次调用前和结束后检查，最后一个请求可能超过剩余 token 额度，不能当作供应商账单的硬限额。问候等独立消息计入累计用量，不重新申请任务额度。

### 保存与恢复

配置、任务摘要、逐动作批次结果、未完成蓝图和用量保存在 `.data/agent-providers.json.agents.json`（`0600`，不含 API Key）。服务重启后恢复原在线角色为待命，未完成任务暂停，不自动调用模型。仅恢复批次格式的执行历史，不再转换旧单动作结果；重启时尚在执行的步骤标为结果未知，剩余动作不自动重放。旧记录迁移为暂停；显式关闭的角色保持关闭。游戏会话和位置仍由世界服务管理；方块持久化取决于世界存储设置。

私聊接收者是游戏会话 ID，不是账户身份。服务重启后原私聊会话失效，私聊任务保持待确认，需在控制台重新布置，不能按同名玩家自动转交。最多保存 50 条 Agent 记录。

服务商保存在本机 `.data/agent-providers.json`（文件权限 `0600`，未加密，请勿分享或提交）。首次启动自动导入 `DEEPSEEK_API_KEY` / `DEEPSEEK_MODEL` / `OLLAMA_MODEL`；已有配置文件后以控制台保存值为准，修改 `.env` 不会覆盖它。页面仅收到 `hasApiKey` 状态；编辑时留空保留密钥。更换地址域名或服务类型必须重新填写密钥。删除服务商不会删除世界方块。

通用服务必须兼容 OpenAI **Chat Completions** 和模型的 JSON 动作输出，原生 Anthropic/Responses 等接口尚未接入。可在兼容设置中关闭 `response_format`，或选择 `max_completion_tokens`。DeepSeek 专用思考字段不会发给其他服务商。本机 Ollama 使用 `http://127.0.0.1:11434/v1`，先在 Ollama 下载模型，再获取列表；配置 Ollama 失败不影响使用 DeepSeek。[Ollama 官方兼容接口说明](https://docs.ollama.com/api/openai-compatibility)。

管理 API 仅接受 `WEB_ORIGIN` 指定页面的 Origin，世界服务仍只绑定本机。`GET /agents/providers` 返回脱敏配置，`POST/PUT/DELETE /agents/providers[/id]` 管理服务商，已有可复用 Agent 关联的服务商不能删除。`GET /agents/providers/:id/models` 查询模型，`GET/POST /agents` 查看/创建玩家，`PUT /agents/:id` 保存已有 Agent 参数（不启动），`POST /agents/:id/task` 布置任务（传 `goal`），`POST /agents/:id/pause` 暂停，`POST /agents/:id/cancel` 取消，`POST /agents/:id/resume` 手动继续（可传 `goal` 新建），`POST /agents/:id/stop` 关闭并离开。写请求使用 JSON。它是本机原型的管理接口，不应直接暴露到公网。

## DeepSeek 命令行（仍可使用）

### 配置与启动

在项目根目录现有 `.env` 中追加以下配置，保留已有数据库等设置。也可以通过环境变量传入；环境变量优先。不要提交 API Key，不要使用 `VITE_*`。

```dotenv
DEEPSEEK_API_KEY=你的DeepSeek_API_Key
DEEPSEEK_MODEL=deepseek-flash
AGENT_NAME=DeepSeek
AGENT_GOAL=探索附近环境，用中文简短介绍你的观察，友好回应玩家。
AGENT_MAX_TURNS=100
AGENT_TOKEN_BUDGET=50000
AGENT_TASK_TIMEOUT_MS=900000
AGENT_ALLOW_EDITS=false
```

启动最新代码的世界服务，再运行独立 Agent 进程。默认世界端口为 2567；当前浏览器 5187 对应的开发世界使用 2577：

当前 memory 模式在普通重启时会丢失方块编辑；更新运行中的世界前须先备份/恢复，或使用数据库持久化配置。

```sh
SERVER_URL=ws://127.0.0.1:2577 pnpm agent:deepseek
```

顶部“玩家”面板将显示 AI 代理身份，模型每轮可以选择移动、聊天或等待。`Ctrl+C` 取消模型请求、停止移动并退出世界；任务完成、等待条件、需要输入或达到保护上限时结束本次 CLI 执行并退出；需要在线待命和事件唤醒请使用控制台托管 Agent。模型配置/认证/余额错误直接结束，其他连续三次失败也停止，不会无限重试。已有 Scout 命令 `pnpm agent` 保持不变。

DeepSeek API 需要有效 API Key 和账户可用额度。运行时会把 Agent 目标、附近方块、玩家昵称和近期公共聊天事件发送给 DeepSeek；没有浏览器音频、文件或环境变量读取工具。

## 思考模式

默认 `thinking: {type: "disabled"}`、每轮最多 512 输出 token，减少交互等待。与官方 SDK 示例相同的思考模式：

```dotenv
DEEPSEEK_THINKING=enabled
DEEPSEEK_REASONING_EFFORT=high
DEEPSEEK_MAX_TOKENS=4096
DEEPSEEK_TIMEOUT_MS=60000
```

未设置 `DEEPSEEK_MAX_TOKENS` 时，开启思考默认 4096，关闭默认 512。JSON 被截断或返回空内容时，该轮不会执行任何动作；可适当提高 token 上限或关闭思考。SDK 自动重试已关闭，每轮至多一次推理请求。

## 可执行动作和边界

- 每批 `actions` 包含 1–8 个以下动作，共享一个 `task` 决策。
- `wait`：结束当前序列，等待下一次观察；只允许位于末尾。
- `chat`：1–240 字公共消息。
- `move`：世界坐标方向 x/z 在 -1..1，跳跃布尔值，持续 100–1500ms；本地以 10Hz 发送输入，取消或结束后发送停止输入。
- `build` / `house`：连续编辑或房屋蓝图，每批最多一个，限制见上文。
- `edit`：需显式设置 `AGENT_ALLOW_EDITS=true` 才允许放置/移除方块。使用观察时的世界版本，服务端继续检查距离、碰撞、基岩、边界和版本冲突。被拒绝的编辑不会自动重放。

`AGENT_MAX_TURNS` 范围 1–200，现在只作为单任务调用上限。旧 `AGENT_CONTINUOUS=true` 不再绕过预算。间隔 `AGENT_INTERVAL_MS` 默认 3000，范围 1000–60000。随机间隔示例：

```dotenv
AGENT_INTERVAL_MODE=random
AGENT_INTERVAL_MIN_MS=4000
AGENT_INTERVAL_MAX_MS=8000
```

上下限均为 1000–60000 的整数，下限不得大于上限，相等时为固定间隔。省略模式时使用 `fixed`。每次间隔只推进一次决策。

每次输入最多 500 个附近方块、16 个玩家、当前明确发来的事件、任务摘要和上轮动作结果。没有任意 shell、文件系统或网络工具。AI 身份与脚本身份一样只是显示标签，不授予额外权限；本机原型仍没有账户认证。

模型自主表现需用真实 Key 实测。自动化测试使用 OpenAI SDK 的模拟 HTTP 响应验证请求格式，并在独立临时世界验证移动、聊天、编辑及离开；这些测试不调用付费模型。

```sh
pnpm check
pnpm test:agent:tasks    # 任务与单次唤醒、暂停、预算、私聊隔离
pnpm test:agent:deepseek  # 自动启动独立临时世界，不触碰正在玩的世界
pnpm test:agents          # 多服务商管理、Origin 校验、密钥脱敏、并发/停止/清理
```

接口依据：[DeepSeek Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion)、[JSON Output](https://api-docs.deepseek.com/guides/json_mode)。
